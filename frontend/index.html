How Fixed Window Rate Limiting Works in RateGuard

1. Discrete Time Slots

Requests are tallied in fixed 10-second intervals starting from each client's first request arrival measured via System.nanoTime(). Time measurement is monotonic and immune to wall-clock drift.

2. Per-Client Isolation

Clients are separated using the X-Client-ID header. If alice exhausts her 5 requests and receives HTTP 429, bob still has all 5 requests available.

3. Atomic Window Reset

Once 10 seconds elapse from the window's creation, the next request resets the counter back to 1 and permits the request with 200 OK and X-RateLimit-Remaining: 4.

4. Boundary Burst Profile

Fixed Window allows up to 5 requests at the end of window 1 (e.g. at 9.9s) and 5 requests at the beginning of window 2 (at 10.1s), permitting 10 requests across a brief 0.2s interval.
